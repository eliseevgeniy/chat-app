# 💬 Масштабируемый многопользовательский чат на Socket.IO и Redis

Учебный проект в рамках изучения Node.js. Представляет собой масштабируемое чат-приложение с поддержкой групповых и личных сообщений, а также синхронизацией состояния между несколькими экземплярами сервера.

## 🚀 Особенности (Features)

- **Масштабируемость:** Использование `@socket.io/redis-adapter` позволяет запускать несколько экземпляров сервера (например, на разных портах), при этом пользователи на разных серверах видят сообщения друг друга.
- **Групповой чат:** Коллективная рассылка сообщений всем участникам (событие `groupMessage`).
- **Личные сообщения:** Отправка приватных сообщений конкретному пользователю (событие `privateMessage`).
- **Единый стейт:** Список онлайн-пользователей хранится в Redis (`online_users`), благодаря чему он актуален для всех экземпляров сервера.
- **Минималистичный UI:** Понятный интерфейс с автоскроллом, разделением групповых и личных сообщений и списком онлайн-пользователей.

## 🛠️ Стек технологий

- **Backend:** Node.js, Express, Socket.IO
- **База данных / Pub/Sub:** Redis
- **Адаптер:** `@socket.io/redis-adapter`
- **Frontend:** HTML5, CSS3, JavaScript (Vanilla)

## ⚙️ Установка и запуск

1. Требования
Убедитесь, что у вас установлены:

Node.js (версия 16+)

Docker (для запуска Redis)

2. Запуск Redis через Docker
В терминале выполните команду:

```bash
docker run -d --name redis-chat -p 6379:6379 redis:latest

(Проверить работу можно командой redis-cli ping — должно вернуться PONG)

3. Установка зависимостей
Перейдите в папку с проектом и установите пакеты:

```bash
npm install express socket.io redis @socket.io/redis-adapter

4. Запуск сервера
Для запуска в обычном режиме (один экземпляр):

```bash
node index.js

Сервер будет доступен по адресу: http://localhost:3000

## 🧪 Как проверить масштабируемость (Мультиэкземплярность)

Чтобы продемонстрировать работу Redis-адаптера, можно запустить два сервера параллельно.

Откройте первый терминал и запустите сервер на порту 3000:

```bash
node index.js

Откройте второй терминал и запустите второй экземпляр на порту 3001:

```bash
PORT=3001 node index.js

Откройте два окна браузера (или обычное и инкогнито):

В первом окне зайдите на http://localhost:3000 и введите имя (например, Alice).

Во втором окне зайдите на http://localhost:3001 и введите имя (например, Bob).

Проверка списка пользователей: В обоих окнах в панели «Онлайн» должны отображаться и Alice, и Bob, несмотря на то, что они подключены к разным серверам.

Проверка группового чата: Alice пишет сообщение — Bob видит его, и наоборот.

Проверка личных сообщений: Alice отправляет личное сообщение для Bob — Bob его получает. Если отправить сообщение пользователю, которого нет в сети, появится ошибка.

## 🧠 Как это работает (Архитектура)

Масштабируемость (Redis Pub/Sub): Когда один сервер вызывает io.emit(), Socket.IO отправляет событие в Redis. Все остальные экземпляры сервера подписаны на канал Redis и мгновенно получают это событие, после чего пересылают его своим подключенным клиентам.

Хранение пользователей: При регистрации socket.id и имя пользователя сохраняются в хэш-таблицу Redis (online_users). Это позволяет любому экземпляру сервера найти socket.id нужного человека для отправки личного сообщения.

Очистка при выходе: При событии disconnect сервер удаляет запись из Redis по socket.id и рассылает всем клиентам обновленный список.
